# 网站部署与维护

## 技术选择

采用 Astro 静态生成：构建时读取 `topics/` 内的 Markdown，生成普通 HTML；浏览器只在导图或交互演示需要时运行相应脚本。

部署采用 Cloudflare Workers 静态资源，不引入服务端渲染、数据库或账号系统。`wrangler.jsonc` 声明 Worker 名称、`dist/` 资源目录、尾斜杠规则、真实 404 页面和自定义域名。

- Worker：`learn-in-public`
- 公开域名：`https://learn.wh1isper.top/`
- 主题路径：`https://learn.wh1isper.top/<主题标识>/`
- 不启用额外的 `workers.dev` 入口和预览网址。

## 持续部署

向 `main` 推送或手动触发工作流后：

1. 安装锁定的依赖。
2. 检查类型、路由与主题分组。
3. 构建网站，检查内部链接、锚点和主题引用边界。
4. 用 Chromium 检查桌面、手机、导图、演示、无脚本阅读与 Worker 静态资源路由。
5. 验证 Wrangler 部署配置。
6. 检查通过后，重新构建同一提交并部署。
7. 访问公开站点，检查主题、笔记和 404 响应。

拉取请求只检查，不接触生产密钥或执行生产部署。发布按同一分支串行执行，避免并发部署互相覆盖。

## GitHub 密钥

仓库的 Actions Secrets 需要：

| 名称                    | 用途                              |
| ----------------------- | --------------------------------- |
| `CLOUDFLARE_ACCOUNT_ID` | 目标 Cloudflare 账号              |
| `CLOUDFLARE_API_TOKEN`  | Worker 静态资源部署与域名管理授权 |

密钥的值不应写入任何仓库文件或文档。更新令牌时通过 GitHub 网页的密钥设置，或在终端安全输入并经标准输入传给 `gh secret set`；不要把令牌直接写入命令历史。

令牌至少需要目标账号的 Worker 脚本编辑权限；首次配置自定义域名还需要相应的域名与路由管理权限。实际权限以 Cloudflare API 与 Wrangler 的校验结果为准。

## 手动验证和发布

在当前终端安全注入 `CLOUDFLARE_ACCOUNT_ID` 与 `CLOUDFLARE_API_TOKEN` 环境变量后：

```bash
npm ci
npm run verify
npx playwright install chromium
npx playwright test
npx wrangler deploy --dry-run
npm run deploy
node scripts/verify-live.mjs
```

日常发布应直接推送 `main`，使用自动流程，保持仓库版本与线上内容一致。

## 故障排查

- **构建失败：** 查看工作流的检查任务，优先处理内容头部、重复路径、无效链接、缺失的主题入口或演示文件。
- **部署鉴权失败：** 检查密钥名称、令牌状态、账号归属和权限，不将令牌打印到日志。
- **域名首次绑定失败：** 检查 `wh1isper.top` 是否由当前账号托管，以及 `learn.wh1isper.top` 是否已有冲突的 DNS 或其他服务绑定。不要覆盖已有服务来绕过冲突。
- **首次 HTTPS 检查失败：** DNS 和证书可能需要生效时间。先检查部署结果，再重新执行线上验证，避免盲目重复部署。
- **导图不能绘制：** 原始 Markdown 和文字代码块仍可阅读。先检查 Mermaid 语法与浏览器测试结果。
